## D1. `/home`: stop gating LCP on the third-party hitokoto API

**Observation.** LCP element on `/en` is `<span class="transition-all duration-300">` carrying the hitokoto string. `RemoteHitokotoQuote` returns `null` while `isLoading`, so the element doesn't paint until `fetchQuoteByLocale(locale)` — which hits `hitokoto.cn` / `dummyjson.com` / `meigen.doodlenote.net` — returns. On slow-4G + cold cache that's the 16.75s LCP.

The hero `<div>` wrapping it has `min-h-[1.5em]` so the layout is reserved, but the *contentful paint* waits for the quote.

**Fix.** Render a non-empty placeholder synchronously, then swap to the remote quote when it arrives. LCP fires on first paint of the placeholder.

File: `apps/web/src/app/[locale]/(home)/components/Hero.tsx:214-254`

```tsx
const RemoteHitokotoQuote = () => {
  const locale = useLocale()
  const t = useTranslations('home')
  const {
    data: hitokoto,
    refetch,
    isRefetching,
  } = useQuery({
    queryKey: ['hitokoto', locale],
    queryFn: () => fetchQuoteByLocale(locale),
    refetchInterval: 300000,
    staleTime: Infinity,
    refetchOnMount: 'always',
    meta: { persist: true },
  })

  // Always render the span so LCP fires immediately. Fall back to the
  // localized default while the remote quote loads — preserves the hero's
  // visual weight and unblocks LCP.
  const displayed = hitokoto ?? t('hero_default_hitokoto')

  return (
    <span className="group inline-flex items-center gap-1.5">
      <span
        className={clsxm(
          'transition-all duration-300',
          isRefetching && 'opacity-0 blur-sm',
        )}
      >
        「{displayed}」
      </span>
      <MotionButtonBase
        disabled={isRefetching}
        className={clsxm(
          'opacity-0 transition-opacity duration-200 group-hover:opacity-100',
          isRefetching && 'animate-spin opacity-100',
        )}
        onClick={() => refetch()}
      >
        <i className="i-mingcute-refresh-2-line text-icon-sm" />
      </MotionButtonBase>
    </span>
  )
}
```

Changes:
- Drop `isLoading || !hitokoto` early return.
- Drop `useState`-style fallback; just use `hitokoto ?? t('hero_default_hitokoto')`.

Risk: visible swap from default text to remote quote when the API resolves. The existing `transition-all duration-300` on the inner span already smooths that. Aesthetically a minor change; perf win is decisive.

Expected: home LCP 16.75s → ~3s (matching FCP+render, no longer gated on external network).

## D2. Home hero h1: drop the `y` translate from the entrance

**Observation.** `/home` CLS jumped from 0.003 to 0.022 after Part B. The biggest contributor is the hero `<h1>` itself with shift score 0.0213. Spec says transforms shouldn't trigger CLS, but the measurement is empirical and motion's implementation apparently registers as a shift in lighthouse's algorithm for this element size (large, above-the-fold).

Easiest fix: remove the `y` translate, keep only the opacity fade. Visually similar (a fade-in rather than a rise) but the LCP-eligible element never reports a position change.

File: `apps/web/src/constants/motion-entrance.ts`

```ts
export const fadeInLcpSafe = (
  delay = 0,
  opts: { duration?: number } = {},
) => ({
  initial: { opacity: LCP_SAFE_OPACITY },
  animate: { opacity: 1 },
  transition: { duration: opts.duration ?? 1, ease: EASING, delay },
})

// New: identical signature to riseInLcpSafe but no y. Use for LCP-sized
// elements where any position change risks a CLS hit.
export const fadeOnlyInLcpSafe = (
  delay = 0,
  opts: { duration?: number } = {},
) => ({
  initial: { opacity: LCP_SAFE_OPACITY },
  animate: { opacity: 1 },
  transition: { duration: opts.duration ?? 0.6, ease: EASING, delay },
})
```

File: `apps/web/src/app/[locale]/(home)/components/Hero.tsx`

```ts
import {
  fadeInLcpSafe,
  fadeOnlyInLcpSafe,
  riseInLcpSafe,
} from '~/constants/motion-entrance'

// Hero h1 is the dominant above-the-fold element. Use opacity-only so no
// transform/position change can register against CLS.
const heroH1Props = (delay: number) => fadeOnlyInLcpSafe(delay)

// Keep rise on smaller elements where the offset is visually nice and
// can't be the LCP element.
const riseProps = (delay: number) => riseInLcpSafe(delay)
const fadeProps = (delay: number) => fadeInLcpSafe(delay)
```

And on the `<m.h1>` JSX:

```tsx
<m.h1
  className="text-center text-title-24 font-normal leading-relaxed text-neutral-9 lg:text-[2.5rem] lg:leading-snug"
  {...heroH1Props(0.2)}
>
  {titleElements}
</m.h1>
```

Verify post-change: rerun lighthouse, expect home CLS back to <0.005.

## D3. `/posts` CLS investigation: PostSortBar fallback didn't help

**Observation.** After C2 (Suspense fallback with reserved 1.25rem height), `/posts` CLS stayed at 0.044 — the same single shift event on `<div data-fetch-at>` with score 0.0438. The fallback either doesn't match the rendered sort bar height exactly, or the shift source isn't `<PostSortBar>` at all.

**Action.** Don't blindly tune the fallback height. Open the lighthouse `posts.report.html` from `2026-05-13-ABC/` → "Avoid large layout shifts" → click the shift entry → it gives the exact pixel delta and a frame thumbnail.

Three possible culprits to verify in order:

1. **`<Suspense fallback>` height still off.** Inspect actual rendered `PostSortBar` height in browser devtools (`mt-5` + `pb-3` + content row). Match the fallback's total height to that.

2. **`<PostListMobileActions>` collapse/expand.** The component contains `<AnimatePresence>` for a back-to-top button. On `lg:hidden` (mobile, our preset), the container has a 2-button grid. Verify no async data dictates which buttons render.

3. **`<PostListDataRevaildate>` revalidating the route.** Located at `src/app/[locale]/posts/data-revalidate.tsx` — calls `revalidatePostList()` server action when data is older than `appStaticConfig.revalidate`. If this triggers during the lighthouse trace, Next.js streams an updated payload mid-load, which can cause a shift. Confirm in DevTools whether a revalidation network request fires within the LCP window. If yes, gate it behind a stable timestamp or move it past `requestIdleCallback`.

Pick one fix based on what the html report points to. No code change baked into this spec — diagnosis first.

## D4. `/timeline`: LCP 24.5s with FCP 2.55s

**Observation.** The year-heading `<span class="text-[4.5rem] leading-none font-extralight ...">` is in the SSR'd HTML and large enough to be the LCP candidate from the first paint. FCP is 2.55s. Yet measured LCP is 24.5s.

Hypothesis: lighthouse keeps finding a *larger* contentful element as the page settles — possibly post-list entries below the year heading rendering progressively, or the year heading itself growing once its font finishes loading (font-display swap retriggering LCP).

Even after A, the timeline page transfers 4.1 MB total. Look for:
- `<Image>` without intrinsic dimensions that paints late.
- Any `'use client'` block whose hydration delays painting of static SSR content (motion wrappers, framer animations not flagged with `lcpOptimization`).
- Inline `style={{ '--gradient-from': ... }}` injection driven by `PageColorGradient` — if applied client-side after hydrate, it can repaint hero.

**Diagnosis steps.**

1. Open `2026-05-13-ABC/timeline.report.html`, find the LCP element timeline. Lighthouse shows each LCP candidate change with timestamps. That tells you whether LCP got reassigned to a different element (truly grew) or the same element repainted (font swap).
2. Compare against `/en/timeline` head: count `<link rel="modulepreload">` and verify no font preload regressed. (Expected ≤2 after Part A.)
3. If LCP reassignment is the year heading repainting at the same position, the fix is to load its font (`Instrument Sans` 400 with the right size adjustment) so the first paint already uses the final glyphs. Check next/font emitted CSS for the size-adjust line — `apps/web/.next/static/css/*.css`, grep for `size-adjust:`. If absent, `adjustFontFallback` may have been disabled somewhere.

If diagnosis points to a specific late-loading element, options:
- Convert that element to use `BottomToUpSoftSpringTransitionView` with `lcpOptimization`.
- Add `next/dynamic` with `{ ssr: true }` to keep SSR but defer client hydration.
- For images: ensure `<Image width=… height=…>` (no fill without sized parent).
